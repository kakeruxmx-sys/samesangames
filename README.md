# PROPNIGHT 2 — THE NIGHTMARE RETURNS

3Dオンライン非対称ホラー（小道具に変身するかくれんぼ）。**人間5人（キラー1 + 生存者4）**で遊ぶブラウザゲームです。
PC（キーボード+マウス）とスマホ（マルチタッチ）の両方に対応しています。

> **重要 / 正直な現状**
> - **このリポジトリは「公開できる状態の実装」ですが、私（開発側）はインターネット上へ公開・デプロイしていません。** 公開URLはまだありません。手順は下の「公開（デプロイ）」を参照してください。TLS（https/wss）用のドメインと証明書、運営者情報（利用規約・プライバシーポリシーの `[運営者名]` など）は運営者側で用意が必要です。
> - **AI・ボット・NPCプレイヤーは存在しません。** 5人の人間が揃わない限り試合は始まりません（サーバーは空きスロットを埋めません）。
> - 実機のiPhone/Androidでの動作確認は**できていません**（Chromiumのモバイルエミュレーションのみ）。下の「既知の制限」を必ず読んでください。

## すぐ試す（ローカル）

必要: Node.js 20 以上。

```bash
npm install
npm run build        # client -> dist/client, server -> dist/server.js
npm start            # http://localhost:8080  (PORT=3000 npm start でポート変更)
```

試合には人間5人が必要です。1台で確認する場合は、**別々のブラウザ/シークレットウィンドウ**を5つ開くか、同じブラウザなら URL に `?profile=a` `?profile=b` … を付けると別プロフィールとして接続できます（例: `http://localhost:8080/?profile=a`）。
LAN 内のスマホで試す場合は `http://<PCのIP>:8080/` を開きます（https ではないため全画面や一部機能が制限される場合があります）。

開発用: `npm run dev`（tsx でサーバー起動。クライアントは `node scripts/build-client.mjs --dev` で再ビルド）。
モデル/マップ確認ビューア（開発用。本番でも配信されます。不要なら `dist/client/viewer.*` を削除）: `/viewer.html?mode=killers`、`mode=survivors`、`mode=props`、`mode=map&id=school`（hotel / factory / mall）、`mode=objects`。

## 遊び方

- **生存者(4人)**: 装置を5つのうち4つ修理 → ゲートに電力 → ゲートを開けて脱出。2人以上が脱出で生存者の勝利。小道具（マップ内の実物）に変身して隠れられる。捕獲されると封印装置に入れられ、45秒以内に仲間が救助しないと脱落（救助後は短時間保護）。3回目の捕獲でも脱落。
- **キラー(1人)**: 生存者を探して攻撃し、封印装置へ。3つの固有能力を持つ（予兆あり・クールダウンあり・対策あり）。
- 試合時間 15分。クイックマッチ（5人集まると自動で5秒カウントダウン）/ カスタムマッチ（ルームコード、ホストがマップ選択、5人揃えば開始）。
- キラー役は、これまでキラーをやった割合が低い人が優先され、同じ人が連続でなりません。キラー役は20秒以内に能力タイプを3Dショールームで選びます（時間切れは**ランダムなタイプ**。操作するのは変わらず人間）。

```

server/src/ index.ts (HTTP静的配信 + WebSocket), rooms.ts (マッチメイキング/ロビー/報酬), match.ts (サーバー権威の試合シミュレーション),
            validation.ts (入力検証/名前フィルタ), profiles.ts (ゲストプロフィール), conn.ts
client/     index.html, style.css, src/{main,ui,game,gl,world,models,menuscene,audio,input,net}.ts (依存ライブラリなしの独自WebGL2レンダラー)
tests/      maps.test.ts, match.e2e.test.ts (スクリプト駆動クライアントでの全試合), browser.test.mjs / browser.results.test.mjs / browser.menus.test.mjs (Chromium)
deploy/     nginx.conf, Caddyfile, propnight2.service      Dockerfile, docs/ (PRIVACY, TERMS, DESIGN)
```

### サーバー権威とチート対策（実装済み）

- 30Hz固定ティックで位置・速度・衝突・能力・クールダウン・修理・捕獲・救助・脱出・勝敗をすべてサーバーが計算。クライアントは「入力の意図」だけを送ります。
- 自分のアバターのみクライアント予測（サーバーと同じ `shared/sim.ts`）+ 受信時の補正。他者は約100msの補間。
- **視界外の情報を送らない**（壁越しの位置はスナップショットに含めない）。位置付きイベントは範囲制限付き。変身中の生存者の「正体」は、キラーにも物として見えるデータだけを送ります。
- 入力の範囲/NaN検証、トークンバケットによるレート制限、フラッド時のキック、IPごとの接続数制限と新規プロフィール作成制限、Originチェック、1ティックあたりの入力数上限、名前のサニタイズ/禁止語フィルタ、定型チャットのみ。
- 切断中のアバターは **60秒間その場で停止**（AIが代わりに動くことはありません）。同じトークンで再接続すると試合に復帰します（旧接続がまだ生きている場合は旧接続を `4001 replaced` で閉じて席を引き継ぎます）。

### 通信・保存

- JSON over WebSocket（`/ws`）。HTTPサーバーが同じポートで `dist/client` を配信します。
- プロフィールは `DATA_DIR/profiles.json`（ゲスト、秘密トークンはSHA-256ハッシュのみ保存）、通報は `DATA_DIR/reports.jsonl`。**永続ディスクに置いてください**。

## 設定（環境変数）

`.env.example` を参照。主なもの: `PORT`(8080) `HOST`(0.0.0.0) `DATA_DIR`(./data) `STATIC_DIR` `TRUST_PROXY`(1でX-Forwarded-Forを信頼) `ALLOWED_ORIGINS` `MAX_CONN_PER_IP` `MAX_NEW_PROFILES_PER_HOUR` `TLS_CERT`/`TLS_KEY`。
`PN_TEST_*` はテスト専用です（本番で設定しないこと）。クライアントは `?server=wss://host/ws` で別サーバーに接続できます（その場合サーバー側に `ALLOWED_ORIGINS` が必要）。

## 公開（デプロイ）

静的HTMLだけではオンライン対戦はできません。**Node.jsのゲームサーバーを常時起動**し、その前にTLS終端（https/wss）を置きます。

1. **Docker**: `docker build -t propnight2 .` → `docker run -d -p 8080:8080 -v pn2data:/data -e TRUST_PROXY=1 propnight2`
2. **VPS + systemd**: `npm install --omit=dev` + `npm run build` したディレクトリを `/opt/propnight2` に置き、`deploy/propnight2.service` を導入。
3. **TLS**: `deploy/Caddyfile`（自動証明書、最も簡単）または `deploy/nginx.conf`（WebSocket upgrade設定込み）。ブラウザは https ページから `wss://` で接続します（`ws://` は混在コンテンツでブロックされます）。もしくは `TLS_CERT`/`TLS_KEY` でNode自身がhttps/wssを提供。
4. 公開前チェック: `docs/PRIVACY.md` / `docs/TERMS.md` の `[運営者名]` `[連絡先]` を実際の内容に置換（雛形であり法的助言ではありません）。`/healthz` でヘルスチェック（ルーム数・接続数）。
5. 公開後に最低限やること: 本物のスマホ（iOS Safari / Android Chrome）での通し確認、負荷試験（下記の制限参照）。

ホスティング例（Fly.io / Render / Railway / VPS など）はいずれも「Node/Dockerが動く・WebSocketが使える・永続ボリュームがある」ことが条件です。サーバーレス型（Vercel/Netlify Functions等）やGitHub Pagesだけでは動きません。

## テスト

```bash
npm test                # 型検査 + マップ静的検証 + サーバーE2E（スクリプト駆動クライアントで全試合）
npm run build && npm run test:browser
#   tests/browser.test.mjs          Chromium 5枚(うち1枚はスマホエミュレーション): タイトル→クイックマッチ→キラー選択→試合→キーボード/タッチ操作→再接続→退出
#   tests/browser.results.test.mjs  短縮試合(PN_TEST_MATCH_SECONDS)で 試合終了→結果画面→XP反映→通報
#   tests/browser.menus.test.mjs    図鑑(全48項目)→設定の保存→名前変更→カスタムルーム(作成/コード参加/退出)→スマホのボタン配置編集→縦画面ガイド
```

`test:browser` は Playwright + Chromium が必要です（ソフトウェア描画なので重く、2CPUでは数分かかります。画質を `low` に固定して実行します）。
最終確認時の結果（開発環境・2CPU・GPUなし）: サーバーE2E 106項目すべて成功 / ブラウザテスト 36項目 + 結果画面テスト 12項目 + メニューテスト 21項目すべて成功。
E2Eが確認していること: 4人では絶対に始まらずAIが入らない / 4マップでの全試合 / キラー勝利・救助・再接続 / 15能力のクールダウン制御 / 速度ハック・テレポート・フラッドの拒否 / 名前フィルタ ほか。
**テストのクライアントはスクリプトであり、本物の人間のプレイテストではありません。**

## 既知の制限（正直に）

- **実機未検証**: iOS Safari / Android Chrome の実機では動かしていません。WebGL2が使えない端末では起動時にメッセージを表示します。iOSでは全画面/向き固定APIが使えず、PWAとしてホーム画面に追加した場合のみ全画面に近くなります。
- **性能は未測定**: 開発環境にGPUがなく、ソフトウェア描画（SwiftShader）でしか動かしていません。30fps(モバイル)/60fps(PC)の目標は設計上の目標であり、**実測で達成を確認していません**。低端末向けに画質「低」(描画解像度60%・描画距離30m・ライト4つ)と自動調整を用意しています。
- **同時接続・負荷**: 単一Nodeプロセス（ルームはメモリ上）。水平スケールは未対応で、負荷試験もしていません。
- **ブロック**: サーバー側のブラックリストではなく、クライアントがチャットを隠し、クイックマッチで相手がいるルームを避けるだけです（最大3回）。
- **見た目**: キャラクター・キラー・マップはプリミティブの組み合わせ（低ポリ）です。商用レベルのアート/アニメーション/収録音源ではありません。
- **ゲームバランス**: 数値は仕様とスクリプトテストを元にした初期値で、実際の人間のプレイテストによる調整は行っていません。
- フレームレートが低い端末ほど、入力送信（フレームごと最大5ティック）が間引かれ移動が遅くなります（チートにはなりませんが体感が悪化します）。
